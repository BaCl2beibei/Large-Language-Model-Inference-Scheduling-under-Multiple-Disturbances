### Metric definitions and boundary convention

The arrival and fixed score windows are nested closed timestamp windows `[start, arrival_end]` and `[start, score_deadline]`; event exactly on either right boundary is included. Residence integrals use the continuous interval and are unaffected by point inclusion. These are not successive reward windows; a future reward implementation must use a consistent non-overlapping convention for adjacent windows.

- All offered requests, including never-sent ones, are the completion-rate denominator. `sent`, `accepted`, engine/API/client first, server/client terminal, cancellation requested/acknowledged and score deadline remain separate fields/events.
- Completion and goodput count only normal **client** success at/before the window end. TTFT is client first positive output minus actual send, not API or engine latency. TPOT is `(client_last-client_first)/(actual_output_tokens-1)` in milliseconds; one token is N/A and is counted separately. Goodput is SLO-qualified completion count / fixed window seconds (TTFT <= 2000 ms; TPOT <= 150 ms; one-token requests use TTFT only).
- `client_output_tokens` sums only positive increments of the cumulative **client received** high-water count inside the window. Identical counts do not extend last output or add tokens; regression is preserved, does not double count recovery, and blocks acceptance. HTTP packet/chunk counts never count as tokens. `completed_output_tokens` is a separate diagnostic for normal completions. Visible partial output before the deadline may contribute token throughput even if its request finishes later; the later output and HTTP success cannot be added to the frozen window.
- Conditional TTFT samples include requests whose first client output is in-window, including later unfinished requests. Conditional TPOT includes in-window normal completions. Report first-output censored count, outstanding IDs and terminal outcomes alongside these conditional distributions. P95 uses linear interpolation at `(n-1)*0.95`.
- `outstanding_request_seconds` integrates **all sent** requests until actual client terminal, clipped to the window. Engine completion or an empty engine queue cannot end this integral. Overdue-first integral begins at send + TTFT SLO. Output-gap integral begins after each positive client output + `max(1s, 5*tpot_slo)` and stops at the next output/client terminal/window end. `longest_no_output_ms` uses the same positive output timeline including its observed tail. Raw packet chunk intervals are reported separately. Exact per-token ITL/P95 ITL is explicitly unavailable.
- After deadline a missing client terminal has score outcome `censored`; cleanup outcome remains unresolved until a known terminal arrives. An unknown terminal is **unknown**, never changed into censoring/success/failure/cancellation. Manual HTTP 499/local cleanup cancellation becomes `manual_cancel` only with a matching requested cancellation and positive acknowledgement. Unconfirmed cancellation stays unknown and makes the cleanup audit incomplete. Genuine client timeout is a distinct outcome.
- Cleanup uses separate client 60-second/server 55-second bounds for the whole cancellation batch, not the old 900-second abort barrier. A request absent from the server lookup is unknown. A backend acknowledgement does not prove all pending output delivery is drained: each producer needs a separately justified `pending_delivery=0` before cleanup audit passes.

### Control and execution

`rl_scheduler/real_bridge.py` contains a CPU-only Manager-owned `ControlArbiter` and a loopback `RealBridge` transport. The arbiter fences a run/episode/version lease and a fixed sorted four-instance `(UUID, epoch)` mapping. A lease is renewed explicitly; expiry or controller exit cannot automatically hand a still-occupied slot to another controller. Release reports draining until no known in-flight task remains. A new controller cannot steal an expired lease. Manager restart creates a different control epoch, so the old episode cannot silently continue.

Decision ID is idempotent across concurrent requests: identical payloads return the stored receipt; changed payloads report conflict; rejected decisions are also retained. Acceptance claims the single global slot before creating the asynchronous task. Busy/cooldown/stale/missing/candidate/version/index/capacity checks are explicit rejections. A transport error never means “not executed”; `RealBridge` queries that same ID on a later call and cannot resubmit a different payload. RPC uncertainty, wrong actual request ID or wrong migration ID keeps the slot occupied. Query can reconcile against the source actor's stored result. Successful/failed/rejected known terminals release the slot, and the five-second cooldown begins at the measured terminal timestamp; occurrence and Manager receipt timestamps remain separate.

`llumnix/real_control.py` adapts live vLLM-v0 queues/block tables and calls the existing `MigrationCoordinator._migrate_out_one_request`. It does not implement a second KV transport. The controlled branch of `Llumlet.migrate_out` awaits a result and carries the expected candidate, decision/migration ID and source/destination epochs. The legacy default remains enqueue-only; Manager's native migration tracking uses an optional await-completion branch. The source selects SR again after the destination prepare RPC, immediately before claiming that exact request. A different candidate is rejected rather than substituted.

Destination prepare installs a per-request epoch guard. Each actual preallocation checks that guard (rejecting a rebuilt destination) and freshly checks `free - ceil(waiting_blocks) - requested_increment >= max(16, ceil(0.05 * total_blocks))`. The normal preallocation path and defaults remain compatible. Controlled transfer RPC uncertainty is preserved independently of the legacy helper's failure return. Unknown outcomes retain source/destination fences and the global slot; they require review/cleanup, not retries or optimistic unlocks.

Manager ordinary migration suppression is enforced in the scheduler via `allow_routine=False` while a controller/fence owns the cluster. The pre-stop/failover branch remains available; scale-down, failover/pre-stop or uncertain native RPCs are recorded as external intervention and invalidate the episode. Native pending tasks prevent takeover. No native routing/migration algorithm was replaced. An optional `initial_instance_id` is a predeclared smoke disturbance on the new streaming endpoint: Manager accepts it only in leased non-PD mode and logs the actual initial route. Active smoke uses saved 70/10/10/10 routing draws shared independently of the action. PPO does not choose the route, and the runner checks the actual route against every sent request's planned route.

`llumnix/entrypoints/vllm/real_control_api.py` exposes allowlisted operations on the existing private API and rejects non-loopback peers. The configured API binds only `127.0.0.1:18080`; no public port, Caddy entry or management-service change was made. Snapshot, acquire/renew, submit/query/release and whole-cluster flush are implemented. Event cursors remain in `RequestLedger`/`LiveEpisodeIO`, preserving complete process streams and collector receipt times. Manager/Llumlet/worker flush acknowledgements and API queue/handler/stream counts are combined with the client's fsynced journal. A new producer, sequence gap, missing watermark or unconfirmed pending delivery makes the episode incomplete.

Per-instance produced-token counters deduplicate cumulative rollback/replay and seed migrated requests with their already-produced prefix, so transferred history is not counted as new destination throughput. The output forwarder now tracks batches from thread submission through queue/actor acknowledgement, including queued and in-flight work. Delivery failure latches unknown delivery status rather than reporting zero. Worker flush waits for its outstanding asynchronous CUDA diagnostic records under a finite bound before fsync acknowledgement. These methods are CPU/mock tested; actual Ray worker placement and GPU instrumentation remain unverified until smoke.
