## 6. P23-02：先把 PPO 的学习链路改正确

### 6.1 保留当前动作和网络

使用现有 13 动作：Stay + 四实例间的 12 个有向迁移。每个源实例的候选请求仍由已有 SR 规则确定。

沿用 `cohort_ppo.py` 的共享实例编码器、方向评分和价值网络。真实路径与模拟路径共用同一因果观测转换、归一化定义、动作顺序及网络输入形状。不要在本轮改成分层策略。

Actor 可见信息只能来自决策时已经获得的数据。真实剩余输出长度、未来到达、未来热点变化、完成后收益不得进入观测。环境内部可以知道固定输出长度来推进请求，但不能把内部真值交给 actor。

### 6.2 三类动作样本必须分开

为每个决策新增可审计字段：

```text
legal_migration_count = sum(action_mask[1:])
actor_eligible = legal_migration_count > 0
action_class = forced_stay | voluntary_stay | migration_attempt
```

含义：

- forced_stay：只能 Stay，不存在动作选择。
- voluntary_stay：存在合法迁移方向，但策略选择 Stay。
- migration_attempt：策略选择了合法迁移；最终成功/拒绝/失败另记。

在 PPO 更新中新增显式配置 `actor_sample_mode=choice_only`；保留旧模式兼容，不能静默改变历史复现实验。

实现规则：

1. 先用**全部决策时间步**计算奖励、完整 return 和优势，不能先删 forced_stay。
2. `choice_only` 下，actor 优势归一化、策略损失、entropy、KL、clip fraction 只使用 actor_eligible 样本。
3. critic 使用全部有效时间步拟合完整 return。策略损失按有选择的样本数归一化，价值损失按各自样本数归一化；记录二者权重，承认这改变了损失相对权重。
4. 保留所有 voluntary_stay，不能按动作类别重采样成 1:1，也不能奖励迁移次数。
5. 某 minibatch 没有 actor_eligible 时跳过 actor 项，避免空张量/NaN；整批都无选择时报告 `no_actor_update`，不能声称策略已经学到东西。
6. 共享编码器可能因 critic 更新而间接改变策略，这与 forced_stay 的直接 actor 梯度为零并不矛盾。

不要本轮改成变长决策间隔/SMDP；先保留原始时间轴完成上述改动。

报告机会数量、forced/voluntary Stay、迁移尝试、成功次数、不同请求数、失败原因，以及条件于 actor_eligible 的迁移概率和选择比例。不能只报总迁移率。

### 6.3 奖励和完整回报

直接复用并验证 `cohort_reward.py`：

```text
每段奖励 = -该段在途请求数量的时间积分 / (N × T_ref)
末段再加入 = -beta × CVaR95(E2E) / T_ref
整轮奖励和 = -(mean_E2E + beta × CVaR95_E2E) / T_ref
```

采用现有 beta=1、gamma=lambda=1 的完整 cohort 口径和既有 CVaR 实现。所有时长统一单位；实际冷却、迁移、被迫等待均包含在时间积分中。

从已接受 replay 的完整 Stay 原始请求日志计算并冻结 `T_ref`，预计约 150.425 秒，最终以重算值为准。不得复用 0.5B 的约 68 秒。它是开发数据归一化常数，不代表最终测试基线。

完整回合真实终止时 V=0；超时截断不能伪装完成。不能把两轮不同策略的数据混成同一 on-policy 批次，不能把 Balanced/Stay 的离线日志灌进 PPO 更新。

### 6.4 采样一致性和探索预检

对冻结策略保存动作前的 observation、mask、action、old_logp、old_value、policy_version。更新前重算 old_logp，检查与采样时一致。执行拒绝保留原动作及回执，不把迁移静默改写为 Stay。

在历史可用观测上离线测量初始策略的迁移概率，只作为分布诊断。现有 Stay bias 为 log(12)，不要先假设它一定合适或一定错误。

- 如果没有合法迁移机会，修观测/掩码或承认数据缺口，不能调 bias 解决。
- 如果有机会但迁移概率几乎为零，先排除实现错误；必要时仅对新实验显式设置初始化 bias，使历史有选择状态上的平均迁移概率落在预先登记的 0.3–0.6 范围，保存原值、新值和原因。
- 不能在真实回合中强制换动作后继续沿用旧 logp；不能为保证迁移数量临时重置策略。

上述初始化只是探索设置，不是正收益策略，也不改变 Stay 的合法性。

### 6.5 必须完成的针对性验证

- mask 只有 Stay 时其概率为 1，直接 actor 梯度为零；测试时隔离 critic 和 entropy 项，避免错误归因。
- voluntary_stay 参与 actor 更新，forced_stay 不参与 actor 归一化和损失。
- 包含连续 forced_stay 的手工小轨迹中，时间成本和返回值未丢失；全 forced_stay 不报 NaN。
- 原始请求日志重构的整轮奖励与目标恒等式一致。
- 采样与更新的 mask/logp 一致；混策略版本、未完成回合、`measurement_only` 数据被拒绝。
- checkpoint 保存/加载后，在同一观测上输出一致；旧配置兼容性通过相关测试。

**验收：** 针对性测试通过，并能用新配置执行一次 CPU 合成链路检查。合成数据只能证明代码可运行，不能冒充真实 on-policy 更新。

- 有足够记录时，迁移耗时中位数相对误差不超过 20%、P95 不超过 30%；明确记录数和尾部估计局限。
- 模拟中 Balanced 相对 Stay 的 mean E2E 和 cost 收益方向均为正，收益幅度与真实值相差不超过 10 个百分点。

参考真实 replay：mean E2E 改善约 19.52%、cost 改善约 16.94%、43 个不同请求成功迁移。必须重算后引用，不把这些数写成模拟环境的预设答案。

对 Q15-A 的负收益案例做同样的符号诊断；如果模拟器把所有迁移都算成收益，说明缺少代价或目标实例干扰，必须报告。如果只有 Q15-B 通过，支持范围仅限 Q15-B，不能宣传为通用调度模拟器。

最多进行两次有依据的修正，优先检查容量/单位、batch 服务曲线、迁移重叠、服务暂停、路由和控制时间。每次保留修正前后的结果。验证集参与修正后，如实称为开发拟合，不冒充独立验证。

**失败处理：** 若服务速度拟合可以、迁移收益符号不可以，P3 状态仍为未通过；保留可用组件，定位需要补采的最小数据。不允许用一个写死的“迁移收益加成”凑出正收益。

## 10. P23-06：最多两轮真实 PPO 采样与一次更新

只有 P2 的 CPU 检查通过、配置和预算冻结后，才能启动本轮真实采样。P3 没通过不必否定 P2，但必须在报告里分别标记；没有足够预算就保留 P2 真实检查待完成。

流程：

1. 生成并保存同一个冻结初始 PPO checkpoint，记录版本和 hash。使用现有服务生命周期、预热、日志和迁移执行路径。
2. 至多运行两个完整 Q15-B cohort，使用不同新 trace seed；两轮采样之间不更新策略。
3. 每轮审计 128/128 完成、真实迁移回执、日志和控制开销。记录 actor_eligible 数量、动作分布、失败和不同请求覆盖。
4. 对全部通过审计的完整同版本 PPO rollout 最多更新一次，输出 choice-only actor 统计和全样本 critic 统计，保存前后 checkpoint。
5. 离线加载新 checkpoint，验证概率、value、梯度和参数变化无 NaN/Inf；不要再开第三轮真实运行来证明性能。
6. 清理本任务拥有的服务、Ray 和 GPU 进程，保存清理证据。

本轮最小真实覆盖要求：至少一个完整审计通过的 cohort、累计至少 20 个 actor_eligible 决策、至少一次经回执核验的成功 KV 迁移。此门槛只证明路径跑通，远不足以证明学到了有效策略。若未达到，记录缺少哪项覆盖，不自动加轮次、不强制迁移凑数。

如果两轮都完整且同策略版本，合并为一个更新批次；只有一轮有效则允许单轮链路更新并明确样本少。全部失败则不更新。

更新前重构 old_logp；记录 actor/critic loss、eligible 样本数、entropy、KL、clip fraction、梯度范数，以及固定诊断状态上更新前后的动作概率。不能要求“迁移概率上升”作为通过条件；正确学习也可能减少某些迁移。

控制开销与发包延迟和已接受的 P0/P1 记录并列展示，硬件/运行条件不同则说明。出现明显新开销先定位，不能把系统变慢归因于策略。

若 P3 已通过历史开发验证且在真实采样前冻结，可用这两轮新日志进一步检查模拟预测误差。但两次随机策略运行不足以检验所有动作收益排序，也不能凭这两轮证明策略优于 Stay。
